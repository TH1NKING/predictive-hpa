PredictiveHPA 控制器已安装到 namespace {{ .Release.Namespace }}。

1. 确认控制器运行：
   kubectl get pods -n {{ .Release.Namespace }} -l app.kubernetes.io/name={{ include "predictive-hpa.name" . }}
   kubectl rollout status deployment/{{ include "predictive-hpa.fullname" . }} -n {{ .Release.Namespace }} --timeout=120s

   命令必须使用本次安装选择的 kubeconfig/context。健康探针通过只说明 manager 健康，
   业务指标是否可用仍需检查 PHPA 的 MetricsReady condition。

{{- if .Values.installCRD }}
2. 确认 CRD 已注册：
   kubectl get crd predictivehpas.autoscaling.brian.io
{{- else }}
2. CRD 由本 chart 之外管理（installCRD=false）。请确认 CRD 已安装：
   kubectl get crd predictivehpas.autoscaling.brian.io
{{- end }}

3. 创建一个 PredictiveHPA（先确保目标 Deployment 已存在）：

   apiVersion: autoscaling.brian.io/v1alpha1
   kind: PredictiveHPA
   metadata:
     name: predictivehpa-sample
   spec:
     scaleTargetRef:
       apiVersion: apps/v1
       kind: Deployment
       name: <你的-deployment>
     minReplicas: 1
     maxReplicas: 10
     targetCPUUtilizationPercentage: 50
     prediction:
       algorithm: EWMA
       alphaPercent: 30
       window: 5m
       horizon: 30s
     scaleDownStabilizationWindowSeconds: 60

4. 检查当前/预测 CPU、当前/期望副本与条件，并结合日志解释决策：
   kubectl get phpa -w
   kubectl logs deployment/{{ include "predictive-hpa.fullname" . }} -n {{ .Release.Namespace }} --tail=100

   新进程需要至少两个有效观测；缺失或陈旧指标时保持 Scale。
   PREDICTED% 是预测结果，不保证领先当前 CPU，也不证明扩容或服务性能改善。
   desiredReplicas 是策略结果；确认实际写入请查看 Scaled Deployment 日志和目标的 spec.replicas。

   可复现的离线回放与独立 Kind 故障验收见仓库 docs/interview-demo.zh-CN.md。
